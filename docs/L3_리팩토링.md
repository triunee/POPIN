# L3 레이어 리팩토링 문서

> 대상: `L3_FSMmain.cpp` 및 L3 모듈군 (`L3_LLinterface`, `L3_timer`, `L3_msg`, `L3_FSMevent`)
> 목적: 전역 변수 집중과 책임 과부하를 해소하고 모듈별 캡슐화를 확립한다.

---

## 1. 배경

리팩토링 이전 `L3_FSMmain.cpp`는 FSM 로직 외에 타이머, 상태 변수, 부스 스캔,
사용자·대기열 관리까지 대부분의 책임을 떠안고 있었다.

| 모듈 | 이전 상태 | 문제점 |
|------|----------|--------|
| `L3_FSMmain` | 전역 변수 30개 이상 집중 | 책임 과부하, 다른 모듈과 경계 모호 |
| `L3_LLinterface` | 메시지 수신 변수만 보유 | FSM 상태 변수가 외부(`L3_FSMmain`)에 노출 |
| `L3_timer` | ARQ·부스선택 타이머만 구현 | 세션·연결·등록·큐 타이머가 `L3_FSMmain`에 산재 |
| `L3_msg` | 인코딩만 구현 | 디코딩은 `data[0]`, `data[1]` 식 직접 파싱 (매직 넘버) |
| `L3_FSMevent` | 완성 | 없음 (참고 모델) |

`L3_FSMevent`는 내부 `eventFlag`를 `static`으로 숨기고 4개 공개 함수만 노출하는
캡슐화 모범 사례였고, 나머지 모듈을 이 수준으로 끌어올리는 것이 목표였다.

---

## 2. 목표와 원칙

- **단일 책임(SRP)**: 각 모듈이 하나의 관심사만 담당
- **캡슐화**: 모든 상태 변수를 `static`으로 숨기고 getter/setter로만 접근
- **대칭성**: `L3_msg`의 인코딩/디코딩을 함수로 대칭 구성
- **명명 규칙**: `모듈_카테고리_동작` (예: `L3_timer_sessionStart`)
- **확장성**: 새 메시지 타입 추가 시 디코딩 함수만 추가하면 되도록

## 3. 모듈 구조

### 리팩토링 후 책임 분담

```
┌───────────────────────────────────────────────┐
│                L3_FSMmain.cpp                  │
│  FSM 상태 전이 · 메시지 핸들러 · 키보드 입력 처리    │
│  보유 변수: main_state / prev_state /           │
│             txBuffer / rxBuffer / pc  (5개)     │
└───────────────────────────────────────────────┘
        │ 호출
        ▼
┌──────────────┬──────────────┬──────────────┬──────────────┐
│ L3_FSMevent  │  L3_timer    │ L3_LLinterface│   L3_msg     │
│  이벤트 플래그 │  타이머 상태   │  FSM 상태 변수 │ 메시지 변환    │
│  (기존 완성)  │  +28개 함수    │  +30개 함수    │ +6개 디코딩    │
└──────────────┴──────────────┴──────────────┴──────────────┘
```

### 모듈별 역할

| 모듈 | 책임 | 공개 인터페이스 |
|------|------|----------------|
| `L3_FSMevent` | 이벤트 플래그 관리 | `setEventFlag` / `clearEventFlag` / `clearAllEventFlag` / `checkEventFlag` |
| `L3_timer` | 모든 타이머·카운터·재시도 상태 | ARQ/부스선택(기존 5) + 세션·카운터·스캔·큐·연결·등록(신규 28) |

| `L3_FSMmain` | FSM 전이 로직과 핸들러만 | `L3_initFSM` / `L3_FSMrun` + 범용 헬퍼 4 + 부스 스캔 4 |

### `L3_FSMmain.cpp` 에 유지되는 변수 (5개)

```c
static uint8_t main_state = L3STATE_SCANNING;  // 현재 FSM 상태
static uint8_t prev_state = main_state;        // 이전 FSM 상태 (디버깅용)
static uint8_t txBuffer[L3_MAXDATASIZE];        // 송신 버퍼
static uint8_t rxBuffer[L3_MAXDATASIZE];        // 수신 버퍼
static Serial  pc(USBTX, USBRX);                // 시리얼 포트
```

## 5. 신규 API 요약

### 5.1 `L3_msg` 디코딩 함수 (Phase 0.5)

인코딩과 대칭되는 디코딩 함수 6종. 매직 넘버 파싱을 대체한다.

```c
void L3_msg_decodeBoothInfo(uint8_t* data, uint8_t* currentCount, uint8_t* capacity,
                            uint8_t* waitingCount, char** description);
void L3_msg_decodeQueueInfo(uint8_t* data, uint8_t* queuePosition, uint8_t* totalWaiting);
void L3_msg_decodeRegisterResponse(uint8_t* data, uint8_t* success, uint8_t* reason);
void L3_msg_decodeBoothAnnounce(uint8_t* data, uint8_t* boothId, uint8_t* currentCount,
                                uint8_t* capacity, uint8_t* waitingCount);
void L3_msg_decodeAdminMessage(uint8_t* data, char** message);
void L3_msg_decodeChatMessage(uint8_t* data, uint8_t* senderId, char** message);
```

**Before / After**

```c
// Before — 매직 넘버 직접 파싱
uint8_t currentUsers = data[0];
uint8_t capacity     = data[1];
uint8_t waitingUsers = data[2];
char*   description   = (char*)(data + 3);

// After — 디코딩 함수
uint8_t currentUsers, capacity, waitingUsers;
char* description;
L3_msg_decodeBoothInfo(data, &currentUsers, &capacity, &waitingUsers, &description);
```

### 5.2 `L3_FSMmain` 부스 스캔 함수 (Phase 2)

전역 `scannedBooths`에 의존하던 `static` 함수를 매개변수 기반 범용 함수로 대체.

```c
void    L3_initBoothScanList(BoothScanInfo_t* booths, uint8_t maxBooths);
void    L3_updateBoothScanInfo(BoothScanInfo_t* booths, uint8_t maxBooths,
                               uint8_t boothId, int16_t rssi, uint8_t currentCount,
                               uint8_t capacity, uint8_t waitingCount);
uint8_t L3_selectOptimalBooth(BoothScanInfo_t* booths, uint8_t maxBooths);
void    L3_displayScannedBooths(BoothScanInfo_t* booths, uint8_t maxBooths);
```

`L3_selectOptimalBooth`의 선택 점수: `RSSI + (여유 있으면 +20) - (대기인원 × 10)`.

### 5.3 `L3_FSMmain` 범용 헬퍼 함수 (Phase 5)

리스트 조작 헬퍼에서 `static`을 제거하고 `L3_` 접두사를 붙여 공개.

```c
uint8_t L3_checkUserInList(User_t* list, uint8_t listSize, uint8_t userId);
uint8_t L3_addUserToList(User_t* list, uint8_t* count, uint8_t userId);
void    L3_removeUserFromList(User_t* list, uint8_t* count, uint8_t userId);
int     L3_getUserWaitingPosition(User_t* waitingQueue, int waitingCount, int srcId);
```

## 6. 코드 변경 패턴

`L3_FSMmain.cpp` 함수 내부는 다음 4가지 패턴으로 일괄 변경되었다.

| 구분 | Before | After |
|------|--------|-------|
| 상태 변수 | `myId = 10;` / `isScanning = 1;` | `L3_LLI_getMyId()` / `L3_LLI_setScanning(1)` |
| 타이머 | `sessionStartTime = us_ticker_read()/1000; isSessionActive = 1;` | `L3_timer_sessionStart()` |
| 메시지 파싱 | `uint8_t boothId = data[0];` | `L3_msg_decodeBoothAnnounce(data, &boothId, ...)` |
| 구조체 접근 | `myBooth.currentCount++;` | `Booth_t* b = L3_LLI_getMyBooth(); b->currentCount++;` |

**예시 — `L3_initFSM()`**

```c
// Before
void L3_initFSM(uint8_t id) {
    myId = id;
    isAdmin = (id >= ADMIN_ID_START && id <= ADMIN_ID_END) ? 1 : 0;
    currentBoothId = 0;
    initializeBoothScanList();
    main_state = isAdmin ? L3STATE_ADMIN_READY : L3STATE_IDLE;
    prev_state = main_state;
}

// After
void L3_initFSM(uint8_t id) {
    L3_LLI_initConfig(id);                                      // id·역할·부스ID 초기화
    L3_initBoothScanList(L3_LLI_getScannedBooths(), MAX_BOOTHS);
    main_state = L3_LLI_isAdmin() ? L3STATE_ADMIN_READY : L3STATE_IDLE;
    prev_state = main_state;
}
```

## 7. 리팩토링 단계

| Phase | 내용 | 산출물 | 상태 |
|-------|------|--------|------|
| 0 | `L3_LLinterface` 확장 — FSM 상태 변수 이동 | 상태 접근 함수 29 + `initConfig` | 완료 |
| 0.5 | `L3_msg` 디코딩 함수 추가 | 디코딩 함수 6 | API 완료 · 핸들러 적용은 후속 과제 |
| 1 | `L3_timer` 모듈 완성 — 타이머 변수 이동 | 타이머 함수 28 | 완료 |
| 2 | 부스 스캔 함수 범용화 | 함수 4 | 완료 |
| 3 | `L3_FSMmain` 전역 변수 제거 | 유지 변수 5개 | 완료 |
| 4 | 함수 내부를 모듈 API 호출로 전환 | — | 상태·타이머 전환 완료 · 디코딩 함수 적용 일부 미완 |
| 5 | 범용 헬퍼 함수 `L3_` 접두사화 | 함수 4 | 완료 |

### 후속 과제

- `L3_FSMmain.cpp`의 `handleBoothInfo` / `handleRegisterResponse` / `handleQueueInfo`
  등 핸들러가 아직 `data[0]` 직접 파싱을 사용한다. Phase 0.5에서 추가한
  `L3_msg_decode*` 함수로 교체 필요.
- 일부 `L3_FSMmain` 내부 `static` 함수(`checkUserInRegisteredList`,
  `removeUserFromActiveList` 등)와 Phase 5 공개 헬퍼 간 역할 중복 정리.

## 8. `static`으로 유지되는 `L3_FSMmain` 내부 함수

FSM 전용 로직이므로 외부 노출하지 않는다.

```
sendMessage, handleConnectRequest, handleBoothInfo, handleRegisterResponse,
handleQueueInfo, printWaitingStatus, displayBoothInfo, scanForBooths,
L3service_processKeyboardInput, L3admin_processKeyboardInput,
startSessionTimer, checkSessionTimer, endUserSession, admitNextWaitingUser,
removeFromWaitingQueue, updateAllWaitingUsers, checkQueueReadyTimeout,
handleQueueReadyTimeout, handleChatMessage, broadcastChatToActiveUsers,
removeUserFromActiveList, checkUserInRegisteredList
```

Phase 2로 대체되어 **삭제된** 함수: `initializeBoothScanList`,
`updateBoothScanInfo`, `selectOptimalBooth`, `displayScannedBooths`.
